# SVN 历史审阅设计（未实现）

本设计不启用端点、不执行网络请求、不改变现有 BASE/工作副本审阅。实现和真实 GUI 验收前不得标记支持 SVN 历史。

## 与 Git 的差异

- SVN 修订号是仓库全局递增编号，不是 commit OID；某一路径的历史可以跳号。不能使用 Git 父提交选择或局部提交图解释 SVN 合并。
- 工作副本可能混合修订、含 switched 子树、稀疏目录和 externals。默认只审阅所选授权工作副本根，不递归访问 externals，不跨 switched 子树合并授权。
- BASE 是本地基线；历史 log/cat 通常需要访问服务器。聚焦刷新和仓库发现不得触发 SVN 历史网络访问。

## 明确网络授权

1. 从已授权的 canonical 工作副本根读取本地 info，得到仓库 UUID、根 URL、工作副本 URL 和相对路径。客户端不能提交任意 URL、命令参数或本地路径。
2. 在首次连接前显示服务器、仓库范围、操作类型、可能使用已有 SVN 凭据、超时及取消说明；URL 用户信息和敏感查询不得进入日志或错误提示。
3. 用户点击“允许本次历史访问”后，签发服务端短期网络授权，绑定 Session、canonical cwd、repositoryId、UUID、规范化服务器与路径范围；最长 5 分钟，可手动撤销。页面关闭或 Session/cwd/仓库变化立即失效。
4. 分页与文件读取均要求同一授权；失效时提示重新同意，不能通过错误重试或聚焦自动续期。授权只允许只读历史访问，不允许 update/checkout/switch/commit/propedit。
5. 第一版只支持 HTTPS 及本地测试用 file 仓库；HTTP、svn、svn+ssh 暂不开放。重定向、跨服务器复制来源不自动继承授权；实现前必须验证客户端实际行为，不能仅依赖 URL 字符串检查。

## 修订与路径身份

- 修订使用规范十进制字符串（0 或非零数字开头），避免 JavaScript Number 精度损失；服务端拒绝 HEAD、BASE、日期表达式、负数及命令片段等客户端输入。
- 首次网络操作解析并固定一个数字 snapshotRevision。后续页固定上界，不跟随新的 HEAD；只读元数据也可能被服务器修改，不能宣称 SVN 日志具有 Git 对象级不可变性。
- 第一版固定路径并 stop-on-copy，不自动跨重命名/复制来源追踪；UI 明确范围。copyfrom-path/rev 仅作文字元数据，不触发额外访问。
- 使用 peg revision 与 operative revision 明确指定身份；路径含 @、空格、中文和百分号必须通过实测参数编码。禁止简单拼接未验证的 URL。
- 每个文件 ID 绑定 UUID、授权范围、snapshot、所选修订、路径和动作；服务端重新核对 log 返回的变更成员，不信任客户端路径。
- 比较 r 与 r-1 表示该路径在仓库修订前后的状态，不称为 Git 父提交。新增/删除显式空侧，复制/替换保留动作说明；r0 为无提交内容边界。

## 资源、认证与错误

- 一页最多 100 项，默认 50；基于最后显示修订减一推进游标，不能把修订差值当 offset。最多展示 10000 项并明确截断。
- 命令输出和每侧正文最多 2 MiB，变更路径最多 10000。XML 禁止外部实体解析；日志正文按纯文本展示，超限不伪装为空历史。
- 每处理器最多 2 个 SVN 历史请求，不排队；每次请求总截止时间建议 20 秒，取消终止子进程，迟到结果被授权/cwd/取消检查丢弃。
- 非交互运行；禁止命令行传入密码、自动接受证书、静默写入认证缓存。使用现有凭据的行为及 --no-auth-cache 必须在 Windows/Linux SVN 版本上验证。失败提示在外部配置认证，不从产品发起交互式登录。
- 本地 file 仓库只用于可控测试；生产若允许 file URL，必须另行限定授权目录，不能将工作副本授权扩大到任意磁盘路径。

## 验证与交付顺序

1. 纯函数：修订字符串、游标、范围身份、URL 脱敏、XML/路径成员与大小上限。
2. 本地 svnadmin 仓库：跳号、r0、新增/删除/复制/替换、含 @/中文路径、混合 BASE、switched/externals 拒绝、只读状态校验。
3. 可控 HTTPS 服务：未同意零网络请求、授权过期/撤销、证书失败、重定向拒绝、离线/认证失败、慢响应取消、无认证缓存写入；不使用用户真实远程仓库进行探测。
4. 授权 RPC：无任意 URL/路径入口，Session 隔离、限流、cwd 失效、取消与总超时。
5. 实际 React/浏览器：授权提示、分页、固定修订两侧、错误与取消、手动/聚焦刷新不自动联网。
6. Windows/Ubuntu × Node22/24 CI，随后在现有 DSH GUI 记录加载版本和实际操作证据；通过后再发布并核对工件。

## 尚需决定的事项

HTTPS 重定向的可强制约束方式、SVN 原生认证缓存行为、URL 规范化规则必须先由测试证明；不能以本文替代实现。跨复制历史、合并信息视图、远程图片比较不在第一版范围。
