# 文件历史跳转同路径：下一批冻结范围

## 当前代码与动机

0.3.41的FileHistory只传递目标commit OID；HistoryPanel保存selected OID，CommitDetails切换时清除文件选择。结果是用户每次跳转都需再次查找路径。本批次仅改善这一导航，不扩展历史搜索、重命名跟踪或SVN。

## 最小实现约束

- FileHistory点击提交时附带已返回的page.path作为导航提示，不把显示文本或任意路径当成RPC授权。
- HistoryPanel将导航路径与目标OID一起保存；普通列表/图选择和搜索清除提示。Session/仓库切换继续重挂载清空。保持图的selected OID接口不变。
- CommitDetails在目标提交默认parentIndex=0的详情加载后，仅以changes中path精确相等且唯一的记录选择其不透明id；后续Diff仍走现有校验RPC。根提交同样适用。
- 不匹配、重复匹配或缺少路径时只显示详情，不发比较请求。不按oldPath猜测改名；删除以服务端changes.path为准。
- 导航提示只消费一次；用户手动选择、搜索或切换父提交后不得重新覆盖选择。考虑目标OID与当前相同：新的显式导航需要可区分事件，不能只依赖commit key变更。
- 父提交默认0不代表文件历史显示的所有改动均在默认父差异中；不匹配时不自动探测其它父提交。

## 验证与收尾

先用纯函数单元测试覆盖唯一精确匹配、未命中、oldPath-only、重复路径和空提示，再以真实组件模拟RPC覆盖跳转选择、同OID再导航、合并默认父与手动父切换、搜索、Session取消及迟到响应。断言比较请求使用详情返回的id，不使用路径。
