# 部分暂存精确模型

状态：纯内容模型已实现并通过39项针对性回归；已用于[内部部分stage适配器](<PARTIAL-STAGE-ADAPTER.md>)，仍不接入用户RPC或界面。当前用户能力仍是受限整文件stage／unstage。

## 不复用显示Diff的原因

现有只读对齐允许换行规范化、显示截断和超预算近似。这些行为可用于阅读，但不能决定写入。部分选择必须保留原始UTF8字节、BOM、LF／CRLF／CR及无末行换行，精确计算超限就拒绝。

## 首个模型范围

按完整原始行token精确LCS，把相邻删除／插入合为原子变更单元，等同行分隔单元。首批支持选择一个或多个完整单元，不宣称替换单元内任意逐行操作。每侧256KiB／4000行、去公共前后缀后20万LCS单元预算，无近似回退。

计划和单元ID绑定完整before／after内容与算法版本。候选重建重新计算规范计划，不相信浏览器给的offset／正文／OID；重复、未知、过期或篡改计划拒绝。全选必须逐字节等于after，空选等于before，任意子集保持未选before内容。

## 接入要求

- Stage before是固定Index，after是捕获work，不是HEAD→work。Unstage候选则从当前Index向固定HEAD选择恢复；展示HEAD→Index的单元不可直接当反向坐标使用。H=a／b／c，I=A／B／c，W=A／B／C时，仅取消第一个暂存变更应得到a／B／c且W不变。
- 部分unstage常会合成新blob，不再天然满足整文件unstage“从不创建对象”的承诺，需采用stage的append-only副作用和未知结果语义。
- 确认要展示候选OID与选择单元，服务器保存候选捕获字节，沿已有对象追加／Index CAS安全链发布；未选暂存和工作文件保持。
- 原子替换单元内逐行选择、冲突、重命名／新增删除、二进制与编码转换另行设计，不通过编辑器显示行号直接写入。
- 计划本身不是授权；Session／仓库／HEAD／完整Index／工作内容与配置仍须绑定和复验。

## 当前验证

模块27项针对性测试通过，含完整字段／额外字段／getter／稀疏数组等篡改拒绝、预算边界、取消与2116对输入的逐子集重建；加上独立golden及暴力最小性oracle，合计39/39通过，无失败或跳过。

### 独立验证

11项原始字节端点／BOM／混合换行／2500行后变更／反向unstage golden测试通过。重复raw-line序列0–4长度，31×31=961对输入用独立暴力子序列oracle检查最小编辑数，并枚举每个计划的全部选择子集，结果通过。

另外补齐默认生产createHandler＋真实Git的stage→unstage RPC round-trip，使用发现返回的仓库ID与status返回的选中ID、默认15秒每请求预算，1/1通过，验证准备无Index写、确认single-use、工作字节与HEAD不变。此前fake Host和real adapter分开测试不被误称为该组合证据。

模型通过不等于用户已获得部分暂存功能，后续RPC、明确确认界面和真实Git验收均为独立门禁。
