# 运行环境与兼容性

## 安装前检查

| 项目 | 要求 |
| --- | --- |
| Node.js | 22 或更新版本；自动测试覆盖22和24 |
| DSH | Web界面；声明兼容0.1.7-rc.2、0.2.0-rc.2、0.2.1-rc.2和0.2.1-rc.5 |
| Git／SVN | 根据项目类型安装，并确保终端可找到对应命令 |
| 操作系统 | 自动测试覆盖Windows和Ubuntu；macOS未验证 |
| 浏览器 | 自动回归使用Chrome；其他浏览器未据此确认 |

插件不是独立网站，不能用另一个Vite服务代替DSH页面。升级DSH到其他版本前，需要重新检查插件接口兼容性。

## Windows的中文SVN路径

某些Windows SVN版本使用系统ANSI代码页接收参数，中文路径可能变成问号。设置LC_ALL不保证解决这个问题。

遇到中文路径失败时，先在终端用同一个SVN可执行文件检查路径。插件不会修改系统区域或替换你的SVN工具。

自动测试使用临时SVN工具，并为它配置UTF-8参数支持；这只适用于测试副本，不修复用户电脑上的SVN，也不随插件分发。维护者细节见[Windows测试脚本](<../scripts/ci-svn-utf8.ps1>)。

## 本地分支切换的额外要求（0.6.0）

默认浏览仍只读，只有独立入口的“预览 → 明确确认”可以切换已有本地 Git 分支；历史引用下拉不写工作区。需要支持 `git switch` 及所用安全选项的 Git，失败时不降级成 checkout／force。仅普通内置 `.git` 目录的非 bare 仓库；linked worktree、分离或符号链接 gitdir、`core.worktree`、detached／unborn HEAD、与目标同名的 tag 均不支持。其他 worktree 占用目标时沿用 Git 拒绝。

工作区必须完全干净，包含未跟踪和被忽略文件；`node_modules`、`dist` 等 ignored 内容也会阻止切换，插件不会替你删除。当前／目标树有符号链接、gitlink 或 `.gitattributes`，工作树路径含符号链接或硬链接、Git元数据含符号链接／硬链接或alternates（本地克隆硬链接对象也不支持），存在 `info/attributes`、过滤器／命令 hooks 配置、稀疏／部分克隆、assume-unchanged／skip-worktree、进行中操作或锁，也会保守拒绝。分支列表最多 1000 条，并受命令输出与整操作时间预算约束。

不提供 stage、commit、stash、force 或网络操作。写入开始后的失败可能结果未知，先手动刷新并核对 HEAD、Index 和工作文件，不能盲重试或假定已回滚。专项测试与同标签发布验证以对应运行报告分别记录，不因新增入口推定当前 GUI 已支持或实机通过。

## 哪些验证已覆盖

0.4.11 已针对 DSH `0.2.1-rc.2` 完成隔离宿主与客户端加载合同检查；具体层次及未验收事项见[本版记录](<releases/0.4.11.md>)。不将版本门禁接受等同于实际页面验收。

0.5.0 的离线宿主合同与发布证据门禁要求上述四个精确版本。2026-11-02 已分别使用四个同版本官方 DSH／ui-slots 依赖树完成本地隔离合同，含版本门禁、真实 Cordis／Connection 注册及卸载、签名 Cookie 交换与 HTTP 认证拒绝、静态资源、RPC HTTP 桥、客户端惰性加载与 SlotRegistry 卸载重载。旧两版本验证唯一 operator 身份，新两版本另验证 guest 拒绝；不以新版 API 冒充旧版能力。客户端 shell／locale 与 Session 存储仍是测试替身，不代表真实页面或持久化恢复验收，也不替代同标签候选包的远程发布证据。验证边界见[0.5.0 记录](<releases/0.5.0.md>)。

- 自动测试：本地Git／SVN行为、权限边界、取消、输出限制。
- 隔离安装：完整包能安装，插件入口能在模拟宿主中注册。
- 隔离Chrome：界面交互与真实编辑器资源；SVN测试连接本地测试服务器。

这些不代表你当前页面已加载新版，也不代表任何外部SVN服务器都可连接。实际环境记录见[实机验证状态](<LIVE-ACCEPTANCE.md>)。

## 安装后检查

1. 重启DSH并刷新原页面，确认VCS入口可见。
2. 选择Session和仓库，查看文件差异及历史。
3. 切换Session，确认没有显示上一项目内容。
4. 确认聊天、工作区和其他插件正常。

安装与回滚步骤见[安装指南](<INSTALL.md>)；不要同时启用旧包与新包。
