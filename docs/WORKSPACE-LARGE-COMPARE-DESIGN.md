# 工作区大文件完整比较方案（未交付）

这是相似重命名批次之后的实现方案，不代表当前正式版已支持。

## 用户入口与范围

Git工作区普通预览超过2MiB时，手动加载完整UTF-8比较。支持全部（固定HEAD对工作区）、已暂存（固定HEAD对固定Index对象）、未暂存（固定Index对象对工作区）。每侧最多8MiB、100000行、单行65536字符；二进制、链接、子模块、冲突Index、SVN和目录不进入此模式。默认高级只读Diff及不完整提示复用历史比较。

## 一次请求内的版本一致性

1. 使用已有Session发现授权，重新解析cwd和仓库，按fresh status确认不透明文件ID。
2. 记录固定HEAD OID，以及选定路径的Index stage／mode／blob记录，不使用读取期间变化的HEAD或Index引用作为正文来源。
3. 按模式选定两侧。历史侧读取固定OID普通blob；Index侧读取stage0且普通mode的固定blob。空侧必须由已确认的新增／删除／untracked状态得出。
4. 工作区侧拒绝全部链接路径组件，使用NOFOLLOW（平台支持时）打开普通文件。打开前、句柄打开后、读取后与最终返回前检查身份、大小、修改／变更时间及命名路径一致性。必须完整有界读取，不依赖一次read填满；取消时关闭句柄。
5. 最后重新确认HEAD、Index和status选择，重验工作区路径和指纹及Session/cwd授权。发生变化返回错误并要求刷新，不返回混合版本的成功结果。

这是读取期间的一致性检查，不是持久快照或系统级锁；读取成功后外部进程仍能修改工作区。不得宣传为绝对原子快照。

## 资源与兼容

large必须严格boolean，仅明确入口接受；复用历史分段／大文件共用的单重读槽，不提高普通预览上限。所有Git步骤传递取消与共用超时预算。现有普通比较请求参数与结果契约保留，不改变SVN行为。

切换选择、模式、仓库或Session清除大文件状态，abort旧请求并释放模型。显式取消恢复普通预览；失败可重试。空白加载及旧内容隐藏都不能保留大文件模型。

## 验证要求

真实Git与RPC覆盖三个模式、暂存后再次修改、新增／删除／untracked／重命名、unborn HEAD、冲突拒绝、读取中变化、Index／HEAD变化、链接替换、Unicode、错误UTF-8及所有容量边界；工作区和Index不被写入。Chrome检查手动加载、完整模型及末尾差异、超时、模式／选择切换、迟到响应与资源释放。

四组合同标签CI、同标签Chrome、四包一致、隔离安装和实际npm／GitHub公开工件验证通过后再正式发布，不安装重启当前DSH。
